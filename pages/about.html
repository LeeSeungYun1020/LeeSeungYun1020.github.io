베이스 플레이트 - 동적 레시피 UI 조합 컴포넌트 메모리 32% 절감

  • 상황
    • 레시피 표시 조건 필터링 기능 추가 필요, 서버 API 일정 지연으로 개발과 검증 시간 부족
    • 레시피를 조합해 UI를 구성할 때 모든 View를 한꺼번에 생성한 뒤 다이얼로그가 열리는 구조
    • 고객센터, 공지, FAQ처럼 사용자가 문제 상황에서 찾는 화면이라, 표시 지연이 사용자 경험과 직결
    • 필터링 기능 추가하면서, View 일괄 생성 구조까지 개선 필요
  • 해결
    • 스크롤이 잦은 특성 고려, RecyclerView로 전환하여 View 일괄 생성 방지
    • UI 상태를 sealed interface와 StateFlow 단방향 흐름으로 재설계
    • 레시피 데이터 변환과 필터링 unit test, mock repository 기반 독립 UI 테스트 도입
  • 결과
    • 저사양 단말 사용자 베이스 플레이트 열림 지연 개선
    • 평균 메모리 사용량 32.2% 감축(59MB→40MB)
    • 서버 API 미완성 상태에서 개발 완료, 마감 내 안정적 배포

SDK 샘플 - 메뉴 DSL로 코드 73% 감축

  • 상황
    • 기존 Java 앱은 메뉴·다이얼로그 생성 시 보일러 플레이트를 여러 파일에 작성 필요
    • 개발사에 제공할 Kotlin 앱 신규 작성과 구조 재설계 필요
  • 해결
    • 리시버 있는 람다로 메뉴 트리를 선언적으로 구성하는 DSL 설계
    • @DslMarker로 중첩 scope에서 잘못된 리시버 사용 차단
    • Compose로 컴포넌트 구성, State Hoisting 패턴 적용
  • 결과
    • 런타임에 설정 변경하는 컨트롤러 앱 추가 개발 - 재빌드 없이 QA가 설정 변경 가능
    • 코드 라인 수 73.3% 감축(7,664줄→2,046줄)
    • 신규 메뉴 추가 시 보일러 플레이트 부담 제거

테마·공통 컴포넌트 - 레이어 설계 및 구현

  • 상황
    • 기능별로 기획자와 디자이너가 달라 동일 컴포넌트 파편화, 신규 기능 추가 시 디자인 재정의
    • 다크 테마 신규 지원, 특정 기능은 고정된 테마로 표시할 수 있는 디자인 레이어 설계 필요
  • 해결
    • 버튼 10종을 2종으로 통합, 앱 바·텍스트 필드·체크박스·스위치를 공통 컴포넌트로 분리
    • 기능 단위로 테마 지정할 수 있도록 구조 변경, 특정 기능은 고정 테마로 제공
    • Light, Dark, DayNight 테마 선택하여 적용할 수 있도록 제공
  • 결과
    • 8종 공통 컴포넌트로 67개 화면 UI 통합, 컴포넌트 재사용으로 신규 UI 구현 비용 감소
    • 다크 테마 및 앱별·기능별 테마 설정 지원, 디자인 일관성 확보

라이브러리 원격 배포 - 의존성 관리 포인트 63→1

  • 상황
    • AAR 파일을 개발사에 전달, 개발사에서 SDK 동작에 필요한 63개 라이브러리 직접 명시
    • 파일 업데이트 누락이나 라이브러리 버전 불일치로 런타임 에러 발생
    • 의존성을 전파할 수 있는 배포 구조로 전환 필요
  • 해결
    • Nexus로 원격 repository 구성, 파일 수동 전달 과정을 저장소 기반 배포로 전환
    • App·Feature·UI·Core·Test 모듈로 분리한 멀티 모듈 구조 설계
    • 버전 카탈로그 도입하여 라이브러리와 플러그인 버전 통합 관리
    • Play Games Service, 서드파티 인증(Naver, Facebook, X) 라이브러리 선택 의존성 분리
    • 사내 CI 연동, 커밋 해시 단위 SNAPSHOT 빌드, Dokka로 API 문서화
  • 결과
    • 개발사가 직접 작성하는 의존성 선언을 63줄에서 1줄로 축소, 신규 서비스 온보딩과 업데이트 시간 단축
    • 수동 AAR 교체와 의존성 설정 누락으로 발생하던 통합 오류 줄여 서비스 안정성 확보

C++ 채팅 SDK - 크로스플랫폼 연동

  • 상황
    • C++ 기반 타사 SDK의 인증·상태·채팅·음성 기능을 모든 플랫폼에서 일관되게 제공 필요
    • id 값이 unsigned로 표현되어 Java 및 JSON 라이브러리에서 타입 호환성 이슈 발생
  • 해결
    • NDK로 C++ 코드를 JVM 환경에서 호출, 기존 Android 인증 로직과 결합
    • id 값을 Kotlin에서는 ULong, Java에서는 Long 타입으로 표현
    • C#·C++ JSON 라이브러리가 unsigned 미지원해 C#은 음수, C++은 String으로 변환해 전송
  • 결과
    • Android, Unity, Unreal에서 동일한 API로 107개 기능 사용 가능
    • 서비스 이용자는 어떤 플랫폼에서든 일관된 채팅 경험 제공받음

AI 코드 리뷰 - n8n 기반 MR 자동 리뷰 워크플로

  • 상황
    • 플랫폼 간 일관성 유지를 위한 반복 패턴이 많아 검증 과정에서 잦은 누락 발생
    • 개발 마감 직전 MR이 누적되어 리뷰 병목 발생
  • 해결
    • n8n, GitLab Webhook, AWS Bedrock으로 MR 자동 코드 리뷰 워크플로 구성
    • 로컬 리뷰 스킬 공유, MR 게시 전 사전 검증
  • 결과
    • 담당 MR에서 검증 후 팀 전체 리뷰 워크플로로 확장
    • 유관 프로젝트에서 사용 요청을 받아 4개 팀 6개 프로젝트에 코드 리뷰 워크플로 적용
